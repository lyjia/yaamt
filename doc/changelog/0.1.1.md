# YAAMT 0.1.1

## Behavior changes

- WAV and AIFF metadata cannot be edited in the GUI, CLI or analyzers until full support lands (#74). Previously, edits appeared to be accepted and then failed on save.
- On M4A files, the initial key, mood, composer, ISRC, MusicBrainz and AcoustID tags cannot be edited, and the key and fingerprint analyzers skip M4A files. Previously, every such write raised an error.
- `yaamt analyze -w` with a BPM analyzer reports files as skipped, because the CLI does not yet select a BPM from the analyzer's candidates (#82). Previously, it failed at save.
- WAV files show empty fields in the Properties window because their tags cannot be read yet (#74). This predates 0.1.1.

## Improvements

- Editors only offer tags the file's format can store. File-view cells for such tags are not editable, and Properties fields are greyed out with the reason as a tooltip.
- Analyzers skip a file, and say why, when its format cannot store every result tag, instead of saving part of the result.
- `yaamt write` names each file and tag it cannot write, writes everything else, and exits with an error.
- The Date tag can be set on MP3, FLAC and M4A files that do not already have one.
- Clearing a field removes the tag from the file instead of leaving an empty tag behind.

## Fixes

- Files without tags, including all WAV files, now show their length, bitrate and format. Previously these were blank, and the length read as zero (#78).
- The total sample count now uses the sample rate. It was computed from the channel count (#78).
- Preferences > Reset to Default no longer turns autosave back on (#84).
- Choosing Cancel at the unsaved-changes prompt on quit no longer leaves playback broken (#84).
- Quitting while a save is running waits for it to finish, so a file is never left partly written (#84).
- With autosave on, an edit made while a save is running is now saved when that save finishes, instead of at quit (#84).
- Edits to tags a file cannot store were silently dropped and reported as saved. They are now prevented, or reported if the file changes on disk after the edit (#79).
- Rows in the file view refresh after a save where some files failed. Previously the files that did save kept showing their old values.
- The Properties window's Publisher field accepted typing but never saved it. It is now greyed out until Publisher is supported.
- Running an analyzer several times in one session could fail with out-of-memory errors until the application was restarted. Analysis worker processes are now replaced regularly so memory is released (#88).
- Analyzer errors now name the type of error. Previously some, such as out-of-memory errors, showed only "Error:" with no message (#88).
